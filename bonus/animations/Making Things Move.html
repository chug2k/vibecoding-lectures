The smallest tool

What even is CSS?

CSS is the styling language of the web. Every element on a page has properties — its color, size, position, shadow. An animation is nothing more than telling the browser to change a property over time. You don't compute the in-between frames; you describe the start and end, and the browser fills the gap.

Two pieces
  • @keyframes — names the steps, from 0% to 100%.
  • animation — attaches them to an element, with a duration and a loop.
  • The properties you animate: transform, opacity, box-shadow…

/* a curve named in steps */
@keyframes pulse {
  0%   { box-shadow: 0 0 0 0   rgba(22,216,154,.5); }
  70%  { box-shadow: 0 0 0 26px rgba(22,216,154,0); }
}
/* attach it: name  duration  loop */
.dot { animation: pulse 1.8s infinite; }

Two @keyframes blocks, no library. The dot animates box-shadow; the button sweeps a highlight with transform + animation. That's the whole vocabulary.

The honest threshold

So… couldn't everything be CSS?

Often, yes — when only one or two things move. A hover, a fade, a status dot, a shimmer: that's CSS, a few lines, no library. Reaching for an animation framework there is overkill.

It gets unwieldy the moment the motion becomes a designed, multi-part scene — many pieces moving in concert, shapes morphing. That's your cue to step up a tool.

Rule of thumb
  • Describe it in one sentence? CSS.
  • One or two properties moving? CSS.
  • A whole choreographed scene? Step up → Lottie.

The designed loop

What is Lottie?

A Lottie is a vector animation stored as data — a JSON file — played by a small runtime. A designer builds it once (in After Effects, or now from an AI skill), and the same file plays on web, iOS, and Android. It stays razor-sharp at any size and weighs only a few kilobytes.

Why reach for it
  • A designed loop that lives in your app — spinner, toggle, like button.
  • Vector: crisp at any size, recolorable, tiny.
  • One file across web + iOS + Android.

Under the hood

Meet the canvas: x and y.

A canvas is a blank grid you draw on with code. (0, 0) is the top-left corner; x grows to the right and y grows down — flipped from the graphs you remember from school. To move something, you change its x and y a little, redraw, and do it again about sixty times a second. That loop — clear, draw, repeat — is the foundation under both canvas and Remotion.

The loop
  • Clear the frame.
  • Nudge each thing's x/y.
  • Draw. Repeat ~60× a second.

Easing · the secret ingredient

Same distance, same time. The top dot is linear (robotic); the bottom eases and feels alive. Easing is just a curve applied to time — and CSS's ease-in-out, Lottie's handles, and Remotion's spring() all pick one for you.

The video tool

What is Remotion?

Remotion is video written in code — in React. Every pixel is a function of the current frame number: f(frame). A renderer steps through the frames one by one and stitches them into an MP4. It's the canvas loop from a minute ago — except run headless and saved to a file you can post.

The shape
  • useCurrentFrame() → the frame number.
  • interpolate() / spring() → turn it into motion.
  • Render → a real .mp4 on disk.

The payoff

One video, or one per row?

Because every frame is a function — of the frame, and of whatever data you pass in — the same code is a template. New data, new MP4: per customer, per pull request, per row in a spreadsheet. And it renders headless from the command line, so it runs in CI — a fresh clip on every release, nobody opening an editor.

The split
  • A designer's timeline → one beautiful video, by hand.
  • Remotion → ten thousand, from one program.
  • Need one video? Any tool works. Need one per row? You need code.

Doing it with an LLM

The model writes all four now.

So the skill isn't typing the code — it's judgment, in three steps: pick the right tool, point the model at the right skill or docs, and check it followed them.

Lottie is the cautionary tale: it fails silently. Bad JSON gives you a blank box — no error, no crash. Referencing a skill is not the same as using one. So you verify by looking at the screen.

Your three jobs
  • Pick the tool — UI element or video?
  • Point it at the skill / docs.
  • Verify it actually followed them.
