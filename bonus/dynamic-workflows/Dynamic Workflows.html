Why bother

A single long conversation goes wrong three ways.

01

Laziness

Does 8 of 50 items well, then quietly starts cutting corners.

02

Self-preferential bias

Grades its own work too kindly. It's invested in being right.

03

Goal drift

Forgets the constraint you set up top — each compaction is lossy.

A fresh team, run by code that counts and never forgets, removes all three.

The most important slide

Workflows cost a lot more tokens.
Reach for one only when the task is:

long ·
parallel ·
adversarial ·
taste-based

For everything else, just ask normally. Gut check: would one smart person doing this in a single sitting cut corners, grade themselves too kindly, or lose the thread?

What real ones sound like

You just describe the job — and name the shape.

"This test fails 1 in 50 runs. Set up a workflow to reproduce it — form competing theories, and don't stop until one survives the evidence."
Loop-until-done · root-cause
"Take my business plan and run a workflow where agents tear it apart from an investor's, a customer's, and a competitor's view."
Adversarial · critique panel
"Here's a folder of 80 resumes — rank them for the backend role and double-check the top ten."
Sort + verify
"I need a name for this CLI tool. Brainstorm a bunch of options and run a tournament to pick the top 3."
Generate · tournament
The pattern hides in the verb: “reproduce,” “tear it apart,” “run a tournament” — name it, the prompt writes itself. — Anthropic, “A harness for every task”

reasoningthoughtfula bit randomimperfect memory

What to keep

Reach for a workflow when the task is long, parallel, adversarial, or taste-based. For everything else, a normal conversation is cheaper and just as good.

The keeper skill: see the shape, and judge honestly whether the fleet was worth it.
