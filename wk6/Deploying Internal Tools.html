Part 1 · Why our own platform

It's about control, not cost.

Vercel is genuinely great — it does a lot, and it's still fine for prototypes. But team tools touch real company and client data, and that changes everything:

Reason 01

Own the data.

On a PaaS, your data lives on someone else's cloud, under someone else's policies. On our box, it never leaves infrastructure we control — full stop.

Reason 02

Secure everything.

Every app sits behind the company identity wall before a single request lands. The perimeter is ours — not a vendor feature we hope is configured right.

Reason 03

Control all the things.

Server, proxy, databases, access policies — ours to inspect, configure, and change. When something matters, we don't file a ticket. We go look.

Evolving The deploy story has evolved before — Dokploy is where it landed, and it may evolve again. What you learn today (containers, proxies, tokens, keys) transfers wherever it goes.

Part 1 · One piece of vocabulary

Docker, in sixty seconds.

Docker packs an app — code, runtime, dependencies, OS libraries — into a container: a sealed unit that behaves identically on any machine.

Dockerfile
The recipe, in your repo. Claude's been adding these to your projects — this is what they were for.
image
The frozen build of that recipe — ready to run, anywhere.
container
A running copy of an image. Your app, live.
Dockerfile
FROM node:22-alpine
COPY . .
RUN npm ci && npm run build
CMD ["node", "dist/index.js"]
# same result on your laptop,
# our box, or any cloud on earth
Dockerfile→ image→ container
The point "Runs in Docker" means "runs anywhere." It's the standard the whole industry ships on — and what lets a self-hosted platform promise to run anything.

Part 2 · The piece nobody's heard of

Traefik, the doorman.

Dozens of apps, one IP, one port 443. Traefik receives every request, reads the Host header, and forwards it to the right container's internal port.

ports
You never fight over them — every app listens on 3000 inside its own container.
config
The "Domain" form is the rule — Dokploy writes it, Traefik reloads live. And every service has a raw-config view: you can always look.
reach
Traefik only routes to containers on dokploy-network. Need Traefik and a database? Both networks — or opaque 500s.
You set this — Dokploy's "Domain" form
Host: guestbook-maria.anduincapital.dev Service: app · Port: 3000 · HTTPS: off
↓ Dokploy compiles it into the Traefik routing rule — live, no restarts
…which means, in plain words
“Requests naming guestbook-maria.anduincapital.dev   → go to maria's app container, port 3000.”

Part 2 · A recommended practice — not a rule

One Postgres
per person.

create once
Your first deploy creates a managed Postgres in your project. (Yours happens in Lab 2.)
reuse
Every app after that shares it — each app gets its own database inside your instance.
why
Every always-on Postgres costs RAM on the shared box — and one instance means one thing to back up, one password to keep straight.
split off
It's a default, you decide: when one project gets big — real traffic, real data — it graduates to its own instance. The deploy skill asks; answer differently any time.

Part 3 · Cloudflare Zero Trust

The wall.

Every request to every *.anduincapital.dev host is checked at Cloudflare's edge — before our server ever sees it. No company SSO session? It never arrives. That's "private by default." And it has a corollary:

Humans

Sail through.

A browser signs in once, gets a cookie, and passes the wall invisibly from then on. Every app you deploy is instantly company-only — zero perimeter code.

Machines

Hit the wall.

A curl, a CI job, an MCP server, a Slack webhook — no browser, no company account. A 302 to a login page it can never solve. Fails silently.

That fact, pointed both ways:1 · our machines going in2 · webhooks coming in…then one separate edge fact:the padlock

Part 3 · Consequence 1 — deploying needs a token

Our machines carry a pass: cloudflared

log in once — everything after is automatic
$ cloudflared access login \
https://taincap.anduin.center
# browser opens → company Google → done
 
$ TOKEN=$(cloudflared access token --app …)
$ curl -H "cf-access-token: $TOKEN" …
✓ our MCP wrapper mints this on every start
⚠ The rite of passage

The minted token goes stale — don't memorize lifetimes, memorize the symptom: Claude's Dokploy calls return an HTML page — "Sign in · Cloudflare Access" — instead of data.

Fix: /mcp → reconnect (the wrapper re-mints). Ten seconds. It will happen to you; it isn't a breakage.

Two tokens, two doors: the Cloudflare token is the building's front door; your Dokploy API key is your badge inside. HTML login page → front door. Permission errors → badge.

Part 3 · Consequence 2 — the sharpest edge

Slack can't
call you.

Webhooks are outside machines POSTing at our domain. They can't sign into our SSO — so they die at the edge with a 302, and the request never appears in your app's logs. For internal tools, these are the ones that bite:

Slack eventsslash commandsClickUp webhooksGitHub webhooks
1
Poll instead of listening. A background job asks ClickUp "anything new?" every minute — the Cauldron shape. At internal-tool volume, almost always enough. (Slack even ships this: Socket Mode — your app dials out, no public URL at all.)
2
Ask for a scoped hole. Service tokens / path-scoped bypass — an admin conversation per path, not a default. A bypassed path is on the open internet: verify signatures yourself.
✓
Not affected: Google sign-in. The OAuth redirect rides the user's browser, which already has the Access cookie. Only server-to-server hits the wall.

Part 3 · Consequence 3 — the padlock

HTTPS off at the door.
https in the env.

Decoder: HTTP is the language browsers and servers speak — plain text, readable by anything in between. HTTPS is the same conversation, encrypted (the padlock) — unlocked by a certificate: an ID the server shows to prove it really is that domain.

🧑‍💻 Browser
HTTPS 🔒──────────→
☁️ Cloudflare
plain HTTP──────────→
🖥 taincap
Dokploy domain HTTPS: OFF · cert: none

Our box holds no certificate — Cloudflare owns the padlock. Force HTTPS at the origin anyway and the two ends bounce forever — ERR_TOO_MANY_REDIRECTS, the #1 first-deploy failure here.

Your env APP_URL=https://…

Your app sees HTTP arrive — so OAuth redirects and secure cookies must be told the real public scheme explicitly.

Not a contradiction They're the two halves of Flexible SSL — Cloudflare owns the padlock; the origin stays plain. The skill hard-codes both.

Part 4 · How the box gets your code

The box pulls.
You don't upload.

At deploy time, taincap does a git clone of your repo. A practice with a purpose:

reproducible
What's running is exactly what's in git — no "works from my laptop" artifacts, and anyone on the team can redeploy it tomorrow.
auditable
The repo's history is the deploy history.
escape hatch
Need to push by hand? You can — Dokploy takes a raw compose file too. Fine for odd cases; git stays the default.
repo access
Public repo → plain HTTPS, nothing to set up (today's lab). Private repo → the box must authenticate → a deploy key:
deploy keyAn SSH keypair: private half in Dokploy, public half on the repo — as read-only.
one per repoGitHub's rule — keys cannot be reused across repos. New private repo → new key. The skill automates the whole dance.
read-onlyLeast privilege, by design. A compromised box could clone your code — never push — and each key opens exactly one repo.
github appThe nicer alternative is instance-wide and admin-only. Deploy keys are what you can do yourself.

Part 4 · A true story from last week

The day every deploy broke.

The starter repos get transferred from a personal account into the org. Routine tidy-up.
What nobody knew: GitHub silently drops every deploy key on transfer.
Next deploy: dead in five seconds at the clone step — ERROR: Repository not found. The error lies. The repo exists; the box just lost the right to see it — and GitHub won't tell an unauthenticated caller the difference.
Re-adding keys needs repo-admin — which the transfer had also reshuffled. Stopgap: HTTPS-with-token clone, deploy, revert so no credential lingers.
Invisible infrastructure. Nobody remembers deploy keys until they break.
Moves break them silently. Transfers and renames give you no warning.
Instant clone failure = authorization. Whatever the error message claims.
