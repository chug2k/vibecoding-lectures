Week 2 — Setup cheat sheet

Get Claude Code talking to Supabase via MCP, end to end. Do these in order.

Read first

Are you in the terminal, or are you in Claude?

If you take one thing from this page, take this. Mixing them up is the #1 reason things go sideways.

The terminal (Terminal.app on Mac, or your VS Code terminal) is your shell. It runs commands like cd, mkdir, ls, npm install, and node. The prompt usually ends in $ or %.

Claude Code is what starts when you type claude in the terminal and hit enter. The prompt changes — now you're chatting with an AI. Your keystrokes are going to Claude, not the shell.

~/projects/deal-tracker $ claude        # <-- in terminal
  …Claude starts…
> make me a folder called src      # <-- now you're in Claude

Inside Claude, do this:

  • Talk in plain English: “create a new folder called src and add an index.ts file”
  • Use slash commands: /mcp, /help, /exit, /clear

Inside Claude, don't do this:

  • Don't type raw shell commands at the Claude prompt: cd ../foo, mkdir bar, npm install. Claude will try to be helpful, but you'll get weird half-states. Just ask for what you want.
  • Don't paste long terminal output expecting Claude to run it — describe what happened instead.
Need a shell command right now? Type /exit to leave Claude → you're back in the terminal → run the command → type claude to come back. (Or in some setups, you can prefix a line with ! to run one shell command from inside Claude — try !pwd.)
Quick check: Is the cursor sitting after a $/%? You're in the terminal. Is it after > with a Claude UI around it? You're in Claude.
Step 1

Install Node.js

Required for most modern JS tooling. Use the official installer.
  1. Go to nodejs.org/en/download/current
  2. Download the installer for your OS (the “Current” release is fine).
  3. Run the installer, accept defaults.
  4. Verify in a fresh terminal: 
    node -v
npm -v
If node -v says “command not found”, close and reopen your terminal so the PATH refreshes.
Step 2

Grab a Supabase Personal Access Token (PAT)

This is what authenticates the MCP server to your Supabase account.
  1. Go to supabase.com/dashboard/account/tokens
    (or: profile picture top-right → Account Settings → Tokens)
  2. Click Generate new token, give it a name (e.g. claude-mcp).
  3. Copy the token immediately — it starts with sbp_… and you only see it once.
If prompted by Supabase: choose “this project” (not global), and “token” (not keys). Tokens are user-scoped, keys are project-scoped — MCP wants a token.
Step 3

Add the Supabase MCP server to Claude Code

One command. Replace $SUPABASE_PAT with the token from step 2.
claude mcp add --transport http supabase -s project \
  "https://mcp.supabase.com/mcp" \
  --header "Authorization: Bearer $SUPABASE_PAT"

Concretely it looks like:

claude mcp add --transport http supabase -s project \
  "https://mcp.supabase.com/mcp" \
  --header "Authorization: Bearer sbp_yourtokenhere"
Already added? Remove and re-add: 
claude mcp remove supabase -s project
Step 4

Verify it works

Restart Claude Code so it picks up the new MCP config, then check.
  1. In Claude Code, type /exit to quit, then re-run claude.
  2. Once in, type /mcp. You should see supabase in the list with a green “connected” status.
If it shows up green: you're done. Try asking Claude to “list my supabase projects” as a smoke test.
Red / disconnected? 99% of the time it's a bad PAT — regenerate it, run claude mcp remove supabase -s project, and redo step 3.
