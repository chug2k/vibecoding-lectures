The vocabulary · four ideas it enforces

The jargon, in plain English.

You'll hear these in the next few slides. They're the principles Superpowers bakes in whether you ask or not — and they're the reason its code holds up.

TDD
Test-Driven Development

Write the test first, then the code that makes it pass.

→If the test goes green, the feature really works — it can't fool itself.

YAGNI
You Aren't Gonna Need It

Build only what's needed now. No speculative extras.

→Less code means fewer bugs and a faster path to done.

DRY
Don't Repeat Yourself

Write a thing once, then reuse it everywhere.

→Fix it in one place — not in ten.

Subagents

A fresh helper agent for each task — no memory of the last one.

→A clean slate every time is exactly why it doesn't drift off-plan.

Honest take

Great for real work. Overkill for tiny stuff.

→Reach for it
  • Real multi-file features with moving parts.
  • When correctness matters and bugs are costly.
  • Long autonomous runs you want to leave alone.
×Skip it
  • One-line tweaks & throwaway scripts — heavier than the task.
  • When you want to hand-drive every step yourself.
Caveats
It's opinionated (TDD / YAGNI / DRY enforced) and talkative; long runs spend more tokens. Optional: set SUPERPOWERS_DISABLE_TELEMETRY to opt out of the version-ping.
