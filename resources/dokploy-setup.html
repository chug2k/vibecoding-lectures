Dokploy setup guide

One-time setup, ~15 minutes: wire your laptop to the team's Dokploy box (taincap) so Claude Code can deploy for you. Four parts: WARP → API key → MCP → skills.

Companion to the "Deploying Internal Tools" workshop deck (Week 6). Everything here is self-paced — no workshop required.

1Cloudflare WARP — verify you're on the team

Why: everything on *.anduincapital.dev — including the Dokploy panel — sits behind Cloudflare Access, the company SSO wall. With WARP connected, your machine carries your company identity: every process on it passes the wall, Claude's Dokploy calls included. No tokens to mint, nothing that expires.

  1. Find the ☁️ in your menu bar. WARP is already installed on team machines. Truly missing? brew install --cask cloudflare-warp, then open Cloudflare WARP from Applications.
  2. Open it → gear → Profile. Team name must say anduin — see the screenshot below.
  3. No team, or logged out? Gear → Preferences → Account → Login with Cloudflare Zero Trust → team anduin → a browser opens → sign in with your company Google account → approve.
  4. Back in the main WARP window, flip the toggle to Connected.

  1. Open taincap.anduin.center — with WARP on, it just loads; there's no Access login. Sign in with your Dokploy account.

Treat the key like a password. It never goes in a chat or a repo — the next section hands it to Claude's MCP registration (your local ~/.claude.json), and that's the only place it lives.

3The Dokploy MCP — put the box in Claude's hands

Why: the MCP server (github.com/Dokploy/mcp) exposes every Dokploy operation — create projects, deploy, read logs — as tools Claude can call. It needs exactly two things: where the box is, and your key. Both ride along as environment variables on the registration — WARP already handles identity, so that's the whole setup.

  1. Register the server — one command (paste your key in place of the placeholder): 
    claude mcp add dokploy-mcp --scope user \
  --env DOKPLOY_URL=https://taincap.anduin.center \
  --env DOKPLOY_API_KEY=<paste-your-key> \
  -- npx -y @dokploy/mcp
    Easiest: paste the command (with your key) into Claude Code and say "add this MCP server" — Claude runs it and your config is updated. --scope user makes it available in every project on this machine.
  2. Restart Claude Code → approve the new server when prompted → /mcp. The first start downloads the package — a quiet minute is normal, not broken.
✓ CheckAsk Claude: "list my Dokploy projects." You want a real answer — and if you haven't deployed anything yet, the right answer is an empty list. Empty list = the whole pipeline works.

4The team's skills — install the playbooks

Why: skills are markdown runbooks Claude loads on demand, and npx skills is a package manager for them (the skills.sh CLI) — npm install, but for agent playbooks. It clones a skills repo using your own git auth and symlinks the skills into ~/.claude/skills. The team's two Dokploy skills encode every gotcha this box has ever inflicted — dokploy-starter picks and scaffolds the right starter for a new app; dokploy-deploy is the whole deploy playbook, so "deploy this to dokploy" just works. They live in AI-Hivemind-Lab/claude-code-shareable-skills.

  1. Install both, globally (available in every project on your machine): 
    npx skills add AI-Hivemind-Lab/claude-code-shareable-skills \
  -g -s dokploy-deploy -s dokploy-starter -y
    Installs are symlinks into ~/.claude/skills — so a later npx skills update moves you to the repo's latest playbooks with no stale copies.
  2. Restart Claude Code. Invoke them as /dokploy-starter / /dokploy-deploy, or just say the words — "which starter should I use?", "deploy this to dokploy" — and they trigger themselves.
✓ CheckAsk Claude: "which dokploy skills do you have?" → it names both. Setup done — your laptop now deploys the way the team's laptops do.
